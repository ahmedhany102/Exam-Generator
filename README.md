# AI-Powered Candidate Portal (MVP)

A candidate-facing job portal built for our **Web Development / Artificial Intelligence / Database / Security** course project.

A candidate signs up, uploads a PDF CV, browses jobs, answers a timed 5-question quiz, and receives an **AI match score** with strengths and weaknesses generated by a Python microservice. Every login attempt and every blocked file is written to an audit log that the candidate can inspect.

---

## 1. Architecture

```
┌──────────────────────────┐          ┌─────────────────────────────┐
│   Frontend (React/Vite)  │          │  AI Service (Python/FastAPI)│
│   localhost:5173         │  POST    │  localhost:8000             │
│                          │ /analyze │                             │
│  - pages & components    │ ───────► │  - validate the PDF         │
│  - services/ (fetch)     │ ◄─────── │  - extract text (PyMuPDF)   │
│  - modular CSS per page  │   JSON   │  - score with TF-IDF        │
└───────────┬──────────────┘          └─────────────────────────────┘
            │ supabase-js (HTTPS, anon key + JWT)
            ▼
┌──────────────────────────────────────────────────────────────────┐
│  Supabase (BaaS)                                                 │
│  - Auth        : email + password, JWT sessions                  │
│  - Postgres    : profiles, jobs, applications, security_logs     │
│  - Row Level Security: every table is protected per user         │
│  - Storage     : private "cvs" bucket (PDF, max 5 MB)            │
└──────────────────────────────────────────────────────────────────┘
```

**Decoupled architecture.** There is no custom backend server. The browser talks to Supabase directly with the *public anon key*, and Postgres **Row Level Security (RLS)** decides row by row what that user may read or write. The only custom server is the AI microservice, which owns one job: turn a PDF + a job description into a score.

## 2. Tech stack

| Layer | Technology | Why we chose it |
| --- | --- | --- |
| Frontend | React 18 + Vite, plain JavaScript (ES6+) | Fast dev server, no TypeScript to defend, components are easy to explain |
| Routing | `react-router-dom` | Real URLs, one `ProtectedRoute` wrapper for all private pages |
| Styling | Plain CSS3, one file per page/component | CSS fundamentals stay visible, no UI library hides them |
| Backend / DB | Supabase (Postgres + Auth + Storage) | BaaS: no server to deploy, and RLS is a real security topic |
| AI service | Python 3.10+, FastAPI, PyMuPDF, scikit-learn | Small, readable NLP pipeline with automatic `/docs` |
| Security | Supabase Auth + RLS + input validation on both layers | Two independent validation layers to demonstrate in the defence |

State management: React `useState` + one `AuthContext`. **No Redux, no Zustand** - deliberately, so every line stays explainable.

## 5. Local setup

### 5.1 Clone and install the frontend

```bash
git clone <repository-url>
cd candidate-portal/frontend
npm install
```

### 5.2 Environment variables

```bash
# inside frontend/
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
```

Open `frontend/.env` and fill in the values from
**Supabase Dashboard → Project Settings → API**:

| Variable | Where to find it | Notes |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | Project URL | e.g. `https://abcd1234.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | `anon` / `public` key | Safe in the browser - RLS protects the data |
| `VITE_AI_SERVICE_URL` | - | Default `http://localhost:8000` |

> **Security note for the defence:** the `service_role` key must **never** appear in `.env`, in the bundle or in the repo. It bypasses RLS completely. Only the `anon` key ships to the browser.

### 5.3 Database

In the Supabase SQL Editor run the files **in this order**:

1. `database/01_schema.sql` - tables, foreign keys, signup trigger
2. `database/02_rls.sql` - enable RLS + policies
3. `database/03_storage.sql` - private `cvs` bucket + storage policies
4. `database/04_seed_jobs.sql` - sample jobs with 5 quiz questions each

Then in **Authentication → Providers → Email**, disable *Confirm email* for the demo so the team can register test accounts instantly.

### 5.4 Run the frontend

```bash
cd frontend
npm run dev
```

Open <http://localhost:5173>. If `.env` is still missing, the app shows a yellow warning instead of crashing - that is expected.

### 5.5 Run the AI service

```bash
cd ai-service
python -m venv .venv
.\.venv\Scripts\Activate.ps1        # Windows PowerShell
# source .venv/bin/activate         # macOS / Linux
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Check it in the browser: <http://localhost:8000/health> → `{"status": "ok"}`, and interactive docs at <http://localhost:8000/docs>.

At the M0 milestone this service returns a **mock** analysis so the frontend can be wired up immediately. See `ai-service/README.md`.

Both servers must run at the same time: the frontend on **5173**, the AI service on **8000**.

## 8. Git workflow

**`main` is protected. Nobody pushes to `main` directly - not even the Team Lead.**

### 8.1 One branch per member

M0 is already committed on `main`, and the four branches `member1` … `member4` already point at that commit. So a member only has to switch to their own branch:

```bash
git checkout main
git pull                                  # once the remote exists
git checkout member1                      # member2 / member3 / member4 for the others
```

If a branch is missing (for example in an older clone), create it once from `main`:

```bash
git checkout -b member1
```

The four branches stay open for the whole project. Work is merged into `main` through **Pull Requests**, one logical feature per PR.

### 8.2 Daily loop

```bash
git add .
git commit -m "feat(auth): add login form with security logging"
git push -u origin member1
```

### 8.3 Commit message convention

`<type>(<scope>): <short description>`

| Type | Use for |
| --- | --- |
| `feat` | a new feature or page |
| `fix` | a bug fix |
| `style` | CSS / formatting only |
| `docs` | README, PLAN, comments |
| `test` | tests (pytest, unit tests) |
| `chore` | tooling, dependencies, config |

Examples: `feat(quiz): add 5 minute countdown timer`, `fix(rls): restrict applications select to the owner`.

### 8.4 Pull Request rules

1. Target `main`, source your own `memberN` branch.
2. Title follows the same convention, e.g. `feat(profile): CV upload with validation`.
3. Description must state **what changed**, **how it was tested**, and **which files are touched**.
4. **One approving review** from a different member is required - the reviewer also runs the flow once.
5. Keep PRs small (one feature). A PR touching files you do not own is rejected.
6. Resolve conflicts locally with `git pull --rebase origin main` and push again.
7. Delete nothing you do not own; never rewrite history on a shared branch (`git push --force` is forbidden on `main`).
8. Before merging: `npm run build` in `frontend/` must succeed and the AI service tests must pass.

### 8.5 Stay up to date

```bash
git fetch origin
git rebase origin/main
```

Rebase keeps the history linear and avoids the "merge commit noise" that makes the final defence confusing.

## 10. Definition of done (per feature)

- The page renders and is reachable through a route in `App.jsx`.
- Data comes from Supabase (or the AI service) - no hardcoded arrays left behind.
- Loading state, empty state and error state are all handled.
- CSS lives in that page's own file, using the variables in `index.css`.
- No `console.log` of secrets or whole CV contents; no `service_role` key anywhere.
- Tested with **two accounts**, including a failed login (a `LOGIN_FAILED` row appears on `/security`).
- Comments explain *why*, not *what*, so every file can be defended line by line.

## 11. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Yellow "Supabase is not configured" banner | `frontend/.env` missing | copy `.env.example`, add keys, restart `npm run dev` |
| Blank page, console shows 401 | Session expired or RLS blocking | log out, log in again; check the policy for that table |
| `new row violates row-level security policy` | Missing INSERT policy, or wrong `user_id` | re-check `database/02_rls.sql` |
| AI call fails with a network error | AI service not running | start `uvicorn main:app --port 8000` |
| CORS error on `/analyze` | Frontend not on port 5173 | keep Vite on 5173, or add your origin to `CORS_ORIGINS` |
| `EMPTY_OR_UNREADABLE_PDF` | Scanned/image-only PDF | use a text-based PDF (known MVP limitation) |
| Upload rejected at 5 MB | Bucket + client + service limits | compress the PDF with any online tool |
