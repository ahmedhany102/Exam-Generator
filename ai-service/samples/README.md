# Sample CVs (to be added)

This folder will hold the PDF files used to demo and test `POST /analyze`.

**Nothing is committed yet on purpose.** At milestone M0 the service is a stub:
it never opens the PDF, it only checks the `%PDF-` signature and the file size.
The stub is therefore fully testable with the tiny fake PDF built inside
`tests/test_analyze.py`, and committing real CVs would only add personal data
and binary bloat for no benefit. Member 4 adds the files below when the real
PyMuPDF text extraction lands (TODO 1 in `main.py`).

## Files Member 4 must add later

| File | What it is | What it is for |
| --- | --- | --- |
| `good_cv.pdf` | A real CV that clearly matches a typical job description: Python, SQL, Git, a few projects. | The happy path. Should produce a high `match_score` and show several `strengths`. Use it in demos and in the manual Swagger test. |
| `weak_cv.pdf` | A real CV from a different field (e.g. graphic design) or with almost none of the required skills. | The "low score" path. Should produce a low `match_score`, a short `strengths` list and a long `weaknesses` list. Proves the analysis is not always positive. |
| `fake.pdf` | A plain text file that was renamed to `fake.pdf` (its first bytes are **not** `%PDF-`). | The `INVALID_FILE_TYPE` error path (HTTP 400). Member 3 needs this to check that the frontend shows a friendly error instead of a broken result. |
| `big.pdf` *(optional)* | Any valid PDF padded above 5 MB (e.g. a PDF with many images). | The `FILE_TOO_LARGE` error path (HTTP 413). Without it you can only test that limit with the generated bytes in `tests/test_analyze.py`. |

## How to test with them once the real implementation exists

```powershell
# Start the service first
uvicorn main:app --reload --port 8000

# Then use http://127.0.0.1:8000/docs -> POST /analyze -> "Try it out"
# and upload good_cv.pdf with required_skills = "python, sql, git".
```

## Reminder

Do not commit anyone's real personal CV to the repository. If you need a
realistic document, write an invented one (a fictional candidate) — that is
enough for the course demo and avoids handling personal data.
